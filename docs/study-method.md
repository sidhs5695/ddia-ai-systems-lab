# Study Method

## Default session: 25–30 minutes

Each session has exactly three parts:

1. **Reading (5–10 min)** — one small DDIA section.
2. **Experiment (15–20 min)** — one observable system behavior.
3. **Takeaway (2–5 min)** — write one sentence or question.

The goal is consistency without streak pressure.

## If progress stalls

Do not advance automatically. Shrink the previous task until it becomes finishable.

Examples:

- "Build a resilient API" becomes "make one endpoint return HTTP 200."
- "Study replication" becomes "demonstrate one stale read."
- "Understand Kafka delivery semantics" becomes "reproduce one duplicate."

## One unfinished project at a time

Do not start the next chapter's implementation before the current chapter's completion criteria are met.

Reading ahead is fine; opening multiple unfinished engineering labs is not.

## Pair-study rhythm

A useful weekly pattern:

- Session A: Contributor 1 implements or measures.
- Session B: Contributor 2 reviews, challenges assumptions, or reproduces.
- Session C: Swap roles or close the current mini-experiment.

## Definition of learning

A chapter is not complete because code exists. It is complete when both contributors can:

- explain the failure mode,
- reproduce it,
- explain the mitigation,
- describe at least one trade-off introduced by the mitigation.
